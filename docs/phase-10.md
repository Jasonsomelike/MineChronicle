## 运行实例监控

PCL 配置发现与游戏运行检测是两件事：配置服务每 15 秒读取登记的文件夹、实例和隔离规则；进程检测约每 3 秒枚举 Java 进程，在内存中解析 `--gameDir`、`--version`，与 PCL 已导入实例匹配。不会启动 PowerShell 或命令行窗口，不记录完整命令行或登录令牌。

一个游戏根目录只建立一套非递归监控，多实例共享时合并显示。启动后补读一次并建立目录监控；普通文件事件只选择发生变化的活动根目录；退出后等待 2 秒防抖，补读最终状态并撤销监控。没有运行实例时不遍历世界目录。5 分钟补偿检查仅覆盖仍在运行的实例，用于弥补通知遗漏；手动扫描和 PCL 配置变更后的导入仍可更新非活动档案。

两次相同范围、相同内容的扫描不会反复写入 SQLite。缓存包含完整标准化统计，并校验档案扫描版本；切换范围、重新启动实例、手动扫描或其他同步服务写入后重新比较。保留读取重试、内容校验、扫描取消和前台扫描优先规则。

界面仅轮询轻量状态；统计汇总与数据健康随档案变化更新，窗口不可见时暂停状态轮询。PCL 的普通元数据检查仅加载实例元数据，配置指纹保存后重启不再因同一配置自动重扫所有世界。

运行识别基于游戏目录与 PCL 配置的匹配。没有标准 `--gameDir` 的自定义 Java 启动命令不会被猜测为某个实例，仍可手动扫描；共享根目录但没有唯一版本参数时明确显示共享目录。

## 资源采样

采样仅包含 MineChronicle 及其自身 WebView 子进程，排除其他软件的 WebView。CPU 为采样区间增量，整机占用除以 32；工作集与专用内存分别计算。Windows 进程 I/O 计数包含文件和进程通信，不等同于物理磁盘吞吐。

CPU 和反复读写减少，专用内存下降；工作集本次反而较高，不能声称所有内存指标均下降。工作集合计包含多个 WebView 进程重复映射的共享页，并不等同于独占物理内存。采样后分进程检查：Rust 主进程工作集约 39 MB、专用内存约 8.7 MB，其余主要为 WebView。以上仅代表本机空闲区间，不代表游戏运行中扫描的峰值。

安装启动时首次保存新的 PCL 配置指纹，扫描版本从 233 变为 234；随后 debug 重启和整个采样区间均保持 234，没有新的世界扫描事务。档案仍为 63 个实例、97 个世界、53 个 UUID、410 份快照、4 条正向增量、0 条回档，历史 104326476 ticks、当前 104329932 ticks，SQLite 完整性和外键检查通过。真实时间线显示 207 条有意义事件，原始快照不删除。既有空统计文件仍为 0 字节，修改时间仍为 2025-11-29 16:34:02。

## Windows 发行

`npm run desktop:package` 构建嵌入前端资源的发行程序及 NSIS 当前用户安装包；`npm run desktop:build` 更新用户一直使用的 debug 程序。两个版本均为 Windows GUI 子系统。应用数据位置由原有 `storage.json` 指向 D 盘，升级不重新创建空档案。
