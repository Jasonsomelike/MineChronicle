# Phase 7：自动观察、增量与回档

版本 0.7.0。只读已保存的游戏根目录；不会改写空文件或把无法读取的时长伪造为零。Phase 5 的 HMCL / Prism 继续暂缓，世界复制去重留到 Phase 8。

## 空文件与读取重试

截图中的 Stats 文件为 0 字节，属于没有可解析内容。文件系统读取层先读取一次，再间隔 100 ms 重试最多 3 次。持续为空或只有空白的文件标记为 `EMPTY_STATS`，界面在独立折叠提示中显示；不进入损坏错误组、不建立零时长历史。非空的非法 JSON 仍显示损坏问题。未知结构仍显示不支持，已有快照和观察游标不丢失。

## 数据规则

SQLite 从 schema 2 事务升级至 schema 3。保留首次历史快照，新增内容哈希、观察游标、增量与回档记录。

- 首次有效观察建立游标，增量为零。升级前未观察的变化不算作升级后的追踪时长。
- 同世界、同 UUID 的相邻有效观察才比较；键顺序变化不产生新快照，其他统计变化会保存快照但不凭空增加时间。
- `new > old` 记录差值；`new < old` 保存旧值、新值、UTC 时间和零增量，同时把游标推进到新值。
- `100 → 200 → 180 → 183` 的追踪合计为 `103` ticks；重复读取、重启、缺失文件均不重复导入历史。
- JSON 递归规范化后使用 BLAKE3；未知模组字段保留，不计算 region 文件哈希。
- 所有存储写入在同一事务中完成，快照关联增量有唯一约束。跨世界汇总使用 i128，IPC 使用字符串，前端使用 BigInt。

## 自动监控

使用 [notify 8.2](https://docs.rs/notify/8.2.0/notify/) 的 Windows 目录通知。显式、非递归监控已导入根目录、saves、世界、stats、players、players/stats。跳过符号链接和目录联接，不监控 region 内容。新增世界及统计目录扫描完成后立即注册。

事件通过原子标志合并，2 秒防抖；30 秒定期检查补偿遗漏通知。自动扫描与手动扫描共享互斥许可。单个损坏文件不会终止监控线程。程序运行期间追踪；暂停开关存入本地数据库，重新打开仍保持暂停。恢复或重新打开后，将最近两次有效观察的正向差记在本次观察时间，并不推断中间的实际游玩日期。

参考 [BLAKE3 Rust API](https://docs.rs/blake3/1.8.7/blake3/)。

## Dashboard

缩减页头和留白，按历史、当前读数、世界与玩家、周/月/累计追踪分别展示。宽窗口为双栏排行，窄窗口自动换行。图标导航、系统风格开关、轻量页面入场和 ECharts 柱长过渡；减少动态效果时禁用动画。数字显示到秒，不在动画期间伪造变化的统计值。

周/月采用本机时区及周一为周起点，按观察时间筛选增量。这些数值不能称为准确的游戏会话统计。回档记录保留旧、新秒数与观察时间。

## 验证

测试覆盖不可变历史、回档后继续累计、丢失和空文件恢复、临时写入重试、重复内容、未知字段变化、schema 2 升级、大整数周/月汇总，以及真实 Windows 通知下的新世界、26.x 布局、防抖、暂停和重启设置。

Rust 测试结束后必须运行 `npm run desktop:build`，确保 `src-tauri/target/debug/minechronicle.exe` 含内置前端。启动和界面回执记录实际版本、执行路径和数据库位置。浏览器截图仅用于布局验收，文件监控通过临时真实目录及桌面进程另行验收。
