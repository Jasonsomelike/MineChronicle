# 0.10.8：自动资源发现与组合筛选

## 为什么游戏可以显示，而档案程序仍然找不到图标

此前界面读取打包时生成的图标目录。它不自动感知之后安装的模组。另一方面，游戏中最终显示的是模型加载器和渲染器生成的结果，并非每个注册 ID 都有一个同名 PNG：

- 材料、机器、工具等可以由 Java 注册和运行时染色生成。
- OBJ、连接纹理、流体容器、分视角模型需要各自加载器。
- 生物皮肤是展开的纹理；没有正确骨骼、UV 和渲染器绑定就不能作为完整模型显示。
- 同一 ID 在不同实例、版本、资源包中可能有不同模型。

本轮联网核对的官方资料（读取成功，2026-09-08）：

- NeoForge 1.21.1 Custom Model Loaders：`https://docs.neoforged.net/docs/1.21.1/resources/client/models/modelloaders/`
- NeoForge 1.21.1 Block Entity Renderers / BlockEntityWithoutLevelRenderer：`https://docs.neoforged.net/docs/1.21.1/blockentities/ber/`

上述文档明确区分自定义模型加载与特殊物品代码渲染。GitHub API 本轮触发匿名请求限额，未把未获取的 GTCEu 源码当作证据。

## 已接入程序的算法

1. 统计行携带实际来源根目录；按实例分组处理本页最多 100 个请求。
2. 找到原版 JAR、模组 JAR、KubeJS / resources 目录、options.txt 启用的资源包。后加载的资源覆盖前面的同路径资源。
3. 建立资源索引；路径、文件大小、修改时间组成签名，30 秒内复用，之后按需要校验。资源包启用顺序也是签名顺序的一部分。
4. 解析普通物品定义、最长 24 层父模型与 `#texture` 引用，并优先读取 Forge / NeoForge 分视角模型的 GUI 定义。原始单层 PNG 直接显示；多层图在原始尺寸合成；标准 elements 模型使用共享渲染器生成 256px 图标。
5. 生物仅在同命名空间存在唯一同名 `.geo.json` 与实体皮肤时自动配对，显示静态姿态；不猜测无关材质。
6. 未识别加载器、循环引用、缺失纹理、动画纹理、需染色模型返回明确原因。旧图标仍可使用，无图时显示原创像素草方块占位图。
7. 普通浏览仅查缺失图标。点击本页刷新可以重查已有图标。添加模组后无需重新编译软件即可发现支持格式的资源。

缓存上限：4 个根目录索引、每根目录 8 个打开的压缩包、100 个解析结果。单资源最大 8 MiB；父链、目录深度、模型复杂度有上限。渲染器按需加载、串行处理，完成后释放材质与几何；没有持续动画循环。游戏目录完全只读。

当前缓存为进程内缓存，重启后按需重新建立。不自动下载或执行模组代码；跨电脑通过重新索引目标实例完成迁移。

## 全量审查结果及限制

对 0.10.7 剩余 **3,443 条“实例 / 类别 / ID”缺失请求**进行只读审查：

| 结果 | 请求数 |
|---|---:|
| 没有同标识物品材质，可能动态注册 | 1,475 |
| 父模型等模型资源不存在 | 698 |
| 生物几何与皮肤不能唯一绑定 | 391 |
| 找到新的可解析候选 | 6 |

其余主要是明确识别但尚未适配的模组加载器。新候选涉及 `irons_spellbooks:invisibility_ring` 和 `ars_nouveau:light_block`，分布在不同实例。**6 是解析候选请求数，不代表 6 个不同物品，也不代表剩余缺失已全部解决。** 光源技术方块还可能在游戏中本就不可见。

完整逐项结果在本地 `.local/runtime-resource-audit-0108.json`，包含 root、ID、类别、资源来源与失败原因。首次完整离线审查约 502 秒；最终复查约 666 秒，结果一致。目录索引改为不逐个打开压缩条目，降低了本轮观察到的 CPU 消耗，但没有证明全量审查墙钟耗时下降。这是逐实例全量诊断，不是界面每次翻页的执行范围。

尚未自动执行任意 Java 渲染器，也没有实现全部模组加载器。继续扩展时应按加载器 ID 增加适配器并用真实资源测试；对于任意动态模型，可靠的最终方案是游戏端在模型烘焙后导出带实例/资源包签名的图标，而不是继续模糊匹配文件名。本版尚未包含游戏端导出模组。

## 组合筛选

实例、世界、玩家统一支持多选组合、全选、反选、清空、搜索和已选置顶。搜索时全选/反选作用于完整列表，界面明确提示。

实例按 PCL 实例身份显示；共享根目录实例分别可选，统计按根目录去重。不同维度按交集查询，同维度按并集查询。空选保持零结果，不能退化为全选。旧单世界跳转仍然兼容，玩家偏好继续保存在原偏好位置。
