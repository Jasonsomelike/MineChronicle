# Phase 8：扫描优化、复制候选与数据健康

版本 0.8.0。Phase 5 的 HMCL / Prism 继续暂缓。游戏文件只读，档案仍位于用户选择的 D 盘。

## 扫描完整性与性能

截图中后面三个 PCL 文件夹显示 0 个实例，复现原因是普通扫描缺少 PCL 全局隔离配置。另有全局发现预算被前面的目录消耗、进入模组生成目录、每条记录都推送进度、后台扫描占用手动扫描许可等问题。

- 输入全部属于 PCL 已注册文件夹时，自动使用唯一正在运行的 PCL；关闭 PCL 后可复用已保存且仍有效的唯一启动器配置。存在歧义时仍需选择，不推测隔离规则。
- 每个输入目录单独拥有 10000 条目发现预算。已识别的版本容器只搜索版本、实例及嵌套 `.minecraft`；版本实例只继续搜索嵌套 `.minecraft`，跳过模组数据。显式选择普通上层目录时仍支持最多 6 层发现。
- 手动扫描优先，后台扫描收到让行信号后取消本轮；手动请求最多等待 15 秒并支持取消。取消结果不会替换界面中已保存的实例和世界。
- 进度最多每 75 ms 推送一次，最终进度始终发送。
- 每次仍读取 stats / level.dat 实际字节，以 BLAKE3 内容缓存复用解析结果；相同文件大小和修改时间不会掩盖内容变化。缓存有容量上限，读取失败不缓存。
- 修改时间超过 5 秒的空统计文件直接标记为尚无数据；刚发生的空白或截断写入仍保留最多 3 次重试。
- 文件事件最多积累 1024 个路径，优先扫描最具体的受影响根目录；每 30 秒完整补偿检查，路径集合溢出时也完整检查。

本机实测：7 个 PCL 文件夹分别为 21、1、1、9、13、5、13 个实例，总计 63 个实例、64 个独立根目录、97 个世界。缺失 PCL 上下文的旧扫描只发现 32 个实例和 54 个世界。

完整发现加首次读取测得约 3759 ms；同一组 97 个已保存世界的扫描从原来的 3489 ms 降至缓存预热后的 251 ms，重复为 250 ms。这些是扫描器耗时，不包含整个界面交互和 SQLite 导入，也不代表所有磁盘上的固定性能。

## 世界与玩家

世界页采用“实例根目录 → 世界 → 玩家”两层折叠，默认全部关闭。关闭项的详细内容不挂载，每页最多 12 个根目录，支持前后翻页、全部收起，以及实例、世界、路径、玩家名和 UUID 搜索。多个实例共享根目录时只列一次世界，所有实例名称均参与搜索。Windows 扩展前缀、分隔符和末尾斜杠按展示用途规范化。

## 复制候选与关联

SQLite schema 3 事务升级至 schema 4，保存候选证据、复核状态及关联详情。每次导入在同一事务内分析当前可读取世界，满足以下条件才创建候选：

- 同一玩家 UUID。
- 完整规范化 stats 内容哈希相同。
- 两边时长相同且大于 12000 ticks，即 10 分钟。
- 世界名称、DataVersion、Minecraft 版本、LastPlayed 等元数据指纹相同；新旧种子字段与世界时间在存在时参与比较。必要字段缺失时不判定。

不计算 region 哈希，不根据同名世界或零时长猜测复制关系。每轮最多分析出 2000 对，达到上限会明确提示。候选保留发现时的证据，重复扫描不重置已做的决定。

数据健康页提供确认复制 / 分支、独立世界、稍后处理和撤销。确认必须选择原世界；后端拒绝多重父世界和循环关联，失败事务不改变既有决定。关联保存 `confirmed_by_user=true`、`inherited_ticks=NULL`、`confidence=unknown`。当前无法可靠计算旧存档的复制时刻，因此界面明确显示“继承时长未知，当前统计尚未扣减”，没有生成虚假的精确去重值。

## 数据健康

展示回档、统计损坏、未知格式、世界目录缺失、不可访问目录、名称待确认及其他扫描问题。空文件仍放在独立的尚无数据提示中。问题可标记已复核、恢复待处理；状态保存到档案，重复扫描不重复生成同一项。文件问题跳转至所属世界，玩家问题按 UUID 查找。支持待处理、已复核、全部分类及每页 12 项。
