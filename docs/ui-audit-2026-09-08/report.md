# MineChronicle UI 调研 · 2026-09-08

本轮直接操作已安装的 MineChronicle 0.10.11（D:\MineChronicleApp\minechronicle.exe），使用真实已有档案。启动仓库中的程序后，单实例机制唤起了这个已安装窗口。窗口截图为 1083×791；原有应用缩放 150%，另做了 100% 对照，结束后恢复 150%。源码只作原因佐证，不等同于已安装程序构建来源校验。本轮没有修改产品代码，也未执行导入、扫描、关联复核或更改自启动。

总体判断：颜色、图标、按钮风格已较统一，主要问题集中在首屏空间分配、统计范围解释、列表浏览效率和设置控件。建议先修复明确的显示错误，再压缩导航与筛选占用，随后整理数据层级。

## 优先处理的问题

**1. P1：缩放下拉框的当前值被裁切。** 图 11 中，组合框只露出字符底部；展开选项后可辨识当前为 150%。用户无法在闭合状态直接确认比例。源码中 `.zoom-controls select` 固定高度 28px，而 `.scan-panel select` 的规则具有同等选择器权重且声明了 9px 12px padding、`font: inherit`，存在样式覆盖风险；这是待用计算样式验证的原因判断，裁切本身已由截图确认。建议给设置内缩放控件明确的尺寸和内边距规则，验证各预设比例下当前值完整可见。位置：src/components/ZoomControls.css:38、src/styles.css:195。

**2. P1：放大后导航、状态和筛选挤压主体内容。** 图 01 中页头、两行导航、状态条与间距占据顶部约 400px；图 03 的首屏只能看到实例和世界筛选，统计内容尚未出现。100% 对照时导航回到一行，但排行仍只在首屏底部开始出现。向下滚动时品牌页头固定，而导航离开可视区。建议缩小品牌栏和状态条的垂直占用；窄有效视口用紧凑导航；让常用页面入口在长列表中仍可到达；实例、世界、玩家采用紧凑筛选摘要，展开后再编辑。保留大字体可读性，不以要求用户缩小字号作为解决方案。位置：src/styles.css:27、178、1887；src/components/ActivityFilters.tsx。

**3. P1：92 / 97 个世界及 63 / 49 个实例相关数字缺少明确口径。** 概览显示“92 个世界 · 63 个 PCL 实例”，世界页显示“49 个实例根目录 · 97 个世界”，统计页还出现“92 份有效玩家统计”。源码佐证：概览 summarize 按所选玩家筛选世界，世界列表按全部有世界的根目录分组；实例数与根目录数也不是同一概念。因此不能据此认定统计错误，但用户很容易怀疑漏记。建议就地标成“所选玩家涉及 92 个世界”“档案共 97 个世界”“63 个实例，共用 49 个有世界的目录”，同时简要解释未计入原因。位置：src/lib/dashboard.ts:30、src/components/Dashboard.tsx:146、src/lib/worlds.ts。

**4. P2：世界列表默认先展示技术分组，用户找不到世界本身。** 图 02 的标题叫“世界与玩家”，首屏内容却是“1.20.1-Forge_47.3.11”等实例分组；折叠后看不到世界名称、最近活动、时长。组内世界本身还有一层折叠；源码显示分组按名称排序。搜索支持实例、世界、玩家，是优点，但浏览路径对记不清名字的用户不友好。建议提供“世界列表 / 按实例分组”两种视图，世界行直接展示名字、所属实例、时长、最近记录；保留当前分组作为辅助。默认全部折叠时，“全部收起”应禁用或改成可展开入口。位置：src/components/WorldLibrary.tsx、src/lib/worlds.ts。

**5. P2：统计表每行固定展示技术字段，压低浏览效率。** 图 05 每行包括“旧版统计与成就 · Minecraft”、中文名称、stat.useItem.\* 原始键、图标、读数和来源；当前视口仅完整显示约三行。中文名称、真实游戏图标和可展开来源都值得保留。建议默认行以图标、名称、数值为主，分类和原始键进入展开详情或“显示技术字段”选项，另提供紧凑密度。不要移除排错所需原始数据。位置：src/components/Statistics.tsx:490。

**6. P2：时间线一条事件占用过多纵向空间。** 图 08 将时间、事件、世界、玩家、增量、完整 UUID 分散展示，当前视口只完整容纳一条记录；已有名字时 UUID 仍始终显示。建议每条事件两行：时间与世界/事件，玩家与增量；UUID 放入详情并提供复制。日期输入已有明确标签，但没有“今天 / 近 7 天 / 本月”等快捷项；建议加快捷范围与一键清除。维持“观察时间不等于实际游戏会话”的说明，避免改成不准确的“今天游玩”。位置：src/components/Timeline.tsx、src/styles.css:1887。

**7. P2：设置说明与实际位置不一致。** 图 10 明确写着“窗口右上角可调整缩放”，图 11 显示实际控件位于下方“窗口与显示”卡片；右上角只有本地档案、托盘提示。建议修正为“可在下方‘窗口与显示’调整缩放”，或提供直接定位控件的入口。位置：src/components/StartupSettings.tsx:88。

**8. P2：低频资源维护按钮占据统计页主操作位置。** 图 04 的“重新检查本页资源”在筛选后、内容前以较大的按钮展示；图 13 中“立即同步”又是不同的操作。用户可能不清楚前者更新的是图标还是统计数据。源码说明前者检查本页本地模型/贴图资源；不要改成自动读取，以免违背现有手动行为。建议明确命名“检查本页游戏图标”，放到资源状态旁的次级操作，结果说明本页匹配数量。位置：src/components/Statistics.tsx:199。

**9. P2：追踪状态缺少一眼可见的业务解释。** 各页都常驻“后台追踪已就绪”，进一步状态藏在“运行状态与观测记录”。设置中另有“PCL 正在运行”和“最近同步”。这些分别描述服务、启动器和配置同步，用户仍需自行判断当前是否在记录游戏。建议摘要按真实运行数据明确显示“等待游戏启动”或“正在追踪 N 个实例”，并将“配置最近同步”与“统计最近保存”清楚区分。这里是状态表达改进，不是判断当前追踪功能失效；本轮没有运行游戏验证。

## 可访问性与证据边界

控件已有相当多的可访问名称；导航有当前页面语义，缩放组合框具有焦点轮廓，正常状态同时使用文字和颜色。无需推倒既有设计系统。

已确认的可读性缺陷是缩放数值裁切；150% 有效视口下的纵向膨胀也会增加低视力用户的滚动成本。灰色次级文字在 100% 对照中偏细小，属于待测风险，没有测量对比度，不作 WCAG 不达标结论。未完成读屏端到端、完整键盘遍历、200% 缩放、不同显示器 DPI、最大化窗口、空档案导入、错误恢复和真实游戏追踪验证。本轮没有使用历史截图、外部竞品或网络评论作为界面缺陷证据。

## 建议实施顺序

先修复缩放裁切和错误位置说明；然后改全局页头/导航与筛选布局，并补齐计数范围；最后优化世界默认视图、统计行密度和时间线。验收重点是相同窗口、100% 和 150% 下都能读清当前设置、理解当前统计范围，并更快找到世界与记录。
