# PCL 进程追踪与观测时段（0.10.10）

## 修复

- 识别 Java 游戏进程后保留其 Windows 进程句柄和实例信息。后续以句柄是否结束判断退出，不再要求每次检查都能读取 `--gameDir`。不缓存或记录完整启动参数、账户令牌。
- 进程句柄指向原进程对象；结束后释放，避免仅靠 PID 造成身份混淆。进程枚举失败或状态查询异常不会当成“全部游戏退出”。
- 游戏退出后，原实例继续保留 8 秒文件监听并分批补扫，捕捉晚到的统计文件。只扫描运行或收尾中的实例；完成后解除监听。
- 将文件事件改为有界批处理，持续保存不会无限推迟扫描。无变化读数继续去重；其他未运行实例不会被增量扫描。

## 观测开始与结束

- SQLite schema 6 新增 `observed_sessions`。从检测到的实例进程变化记录观测区间，时间存储为 UTC 秒，界面显示本地时间到秒。
- 单次实例运行、相互重叠的同实例进程合并为一个区间；最后一个进程退出后记录结束。不同实例分别记录，重新启动新建区间。
- 暂停追踪、退出本软件或恢复未完成观测时，区间标记为“观测中断”，不伪造游戏结束时间。暂停后恢复会新开观测区间。
- “实例观测时段”折叠面板提供最近 50 条记录，全部历史保存在档案。开始/结束检测通常有约 3 秒轮询延迟；扫描或系统繁忙可能进一步延迟。
- 这是进程观测时间，包含加载、菜单等阶段。游戏统计仍使用存档 ticks；历史漏记读数可以补回，但不能据此还原历史游戏开始/结束时间。

## 验证

- 原生 Windows 测试启动独立合成 `javaw.exe`，识别后清除其自身启动参数，验证仍可连续识别；进程终止后消失，无关 Java 不会继承身份。
- 追踪集成测试覆盖查询失败保留追踪、退出后延迟写入、未运行实例不扫描、重复保存不重复入账、回档、监控暂停与恢复。
- 观测记录测试覆盖并行实例、重复探测、同实例重启、结束时间、秒精度、观测中断与持久化。
- 无头浏览器使用模拟 IPC 验证观测表格、收尾状态、切页保留与窄屏布局。真实桌面程序另验证嵌入资源及后端/前端版本。

维护工具 `reconcile_roots` 可补扫指定根目录，保留既有导入目录与首次历史基线，不生成追溯的观测时段。
