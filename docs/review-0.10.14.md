## 已复现的问题

### P1：恢复预览可与当前选择不一致

位置：`src/components/ArchiveSettings.tsx:203`、`:216`、`:245`。

校验 A 备份时，文件路径输入及备份列表仍可修改。改为 B 后，A 的迟到结果无条件调用 `setPreview`，预览里又不展示文件路径；用户确认后提交的是 `preview.path`，即 A。Playwright 实测输入框为 `D:\QA\B.sqlite3`，提交的恢复路径为 `D:\QA\A.sqlite3`。测试使用模拟 IPC，没有执行真实恢复。

建议为校验添加请求序号，并将预览绑定到规范化路径和摘要；改选即作废预览，迟到结果丢弃。确认区明确显示目标文件；安排恢复时核对预览摘要，文件发生变化则重新确认。同一路径重新校验失败也应清除旧预览。

### P2：启动旧读取仍可覆盖已刷新的档案

位置：`src/components/ScanPanel.tsx:137`、`:196`、`:320`。

首次加载、PCL 刷新和追踪刷新分别调用 `loadLibrary`，各自最终写入同一个 `report`。`useResource` 只隔离自身请求，不能协调这三条来源。实测先让后台读取显示新档案，再释放较旧的启动读取，新档案被覆盖；之后经过 5.4 秒轮询仍未恢复，因为 revision 已提交、未发生变化。

建议将档案读取归并到单一协调入口，提交时比较统一请求代数或数据库 revision；目录输入仍用独立的 dirty 标志保护。测试需覆盖不同来源之间的请求竞争，不能只测同一 hook 内的筛选竞争。

### P2：按状态筛选后，历史分页仍可能重复

位置：`src-tauri/src/database/sessions.rs:194`、`:215`。

最大 ID 边界可挡住新增记录，无法冻结边界内记录的状态。51 条样本中，ID 51 起初运行中，其他已结束；筛选“已结束”第一页返回 50…31。ID 51 结束后进入筛选集合，第二页变成 31…12，ID 31 重复，而且 `new_records=0`，没有刷新提示。

建议使用固定匹配 ID 集合的查询快照，或采用基于最后一条 ID 的游标分页，并明确跳页与筛选计数的刷新语义。增加“状态变化期间翻页”的合约测试。

### P2：备份目录故障会漏报自动备份错误

位置：`src-tauri/src/database/backup.rs:230`、`src-tauri/src/commands/backup.rs:47`。

创建目录在统一错误记录闭包外，失败后直接返回；后台线程丢弃返回值，`policy.error` 保持为空。临时档案实测：将已配置的空备份目录替换为普通文件，自动备份失败返回 Windows 错误 183，状态接口对应的错误字段仍为空。原备份不会被删除，但界面无法提示本次保护失败。

建议将路径准备、快照、校验、登记、清理全部纳入错误状态；至少记录最近尝试时间、最近成功时间和失败阶段。策略文件本身不可写时，应提供内存状态，避免错误记录依赖同一故障磁盘。

## 可选优化

- 待恢复状态增加目标文件、安排时间和“取消恢复”，避免用户只能重启后接受替换。
- 提供系统文件选择器，减少恢复时复制完整路径的步骤；现有备份列表和手动路径保留。
- 观测接口仍按页读取完整历史并重新归因。可以在数据 revision 不变时复用结果，先测含增量的端到端查询再决定是否缓存；当前证据不能据此断言实际界面卡顿。
