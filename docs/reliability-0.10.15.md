# MineChronicle 0.10.15

## 复审问题修复

- **恢复预览与文件绑定**：改选文件立即使旧预览失效，迟到的校验结果不会覆盖当前选择；重新校验失败会清空旧预览。确认区显示完整路径，安排恢复时核对预览摘要并锁定源文件，防止文件中途变化。需要选择独立备份，带未合并 WAL 的活动数据库会被拒绝；本软件创建备份仍通过 SQLite backup API 包含已提交 WAL 数据。
- **启动读取统一协调**：初始加载、PCL 和追踪 revision 统一驱动同一个档案读取入口，共用请求失效保护。迟到的旧启动读取不能覆盖新档案，仍保护已编辑的扫描目录。
- **状态变化不再挤动分页**：后端固定查询快照，翻页沿用快照令牌。新增或状态变化只提示刷新，筛选计数、本页记录及筛选累计保持在上次刷新时的状态；全部历史累计和运行状态随数据更新。点击刷新重新建立查询。
- **备份目录故障可见**：目录准备纳入统一错误记录，保存最近尝试和成功时间；策略文件不可写时，后台服务保留内存错误，界面仍能提示失败。失败不删除旧备份。

## 同步完成的优化

- 待恢复状态展示来源文件和安排时间，支持取消；取消先撤销激活标记，保留当前档案及恢复前备份。
- Windows 系统文件选择器可直接选择备份；支持取消，保留备份列表和路径输入。
- 使用同一个 SQLite 连接的 `data_version` 判断缓存失效。未变化时翻页不重新执行归因；变化后更新缓存，并保留用户正在阅读的快照。最多保留 8 个查询快照，共享历史数据；旧令牌失效后可点击“刷新观测”重新查询。没有新增数据库物化表或删除历史。

## 缓存测量

运行 `cargo run --manifest-path src-tauri/Cargo.toml --example bench_observation_cache`，用独立临时档案测量每条会话配 5 条增量的完整观测查询。2026-09-18 本机调试构建结果：

| 会话 / 增量     | 未缓存查询 | 缓存首次查询 | 缓存后查询平均（30 次） |
| --------------- | ---------- | ------------ | ----------------------- |
| 10 / 50         | 2.212 ms   | 0.623 ms     | 0.010 ms                |
| 1,000 / 5,000   | 20.594 ms  | 23.081 ms    | 0.073 ms                |
| 10,000 / 50,000 | 249.609 ms | 263.790 ms   | 0.665 ms                |

首次缓存仍需完整计算；改善来自复用不变数据。每次对结果逐项核对，不设绝对时间门禁。上述计时不是桌面 UI 响应耗时，也不与上一版本的 release 归因微基准混用。
